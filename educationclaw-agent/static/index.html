How this agent works

An AI agent is a loop around a language model. The model cannot do anything by itself — it can only write text. The loop (plain Python in agent.py, called the orchestrator) turns that text into actions:

  1. Build context — the three brain files, the tool list, all memories and the conversation so far are pasted into one big prompt.
  2. Ask the model — one ordinary HTTP request (see the LLM calls panel: nothing is hidden).
  3. The model picks a tool — its reply ends with a small JSON block like {"tool": "get_time", "args": {}}.
  4. Run the tool — the orchestrator executes that one function and appends the result to the conversation. Back to step 1.

The loop ends when the model calls the special tool finish — being done is just another tool call.

Tasks line up in a queue and run one at a time. The model can split big work into subtasks with its add_task tool — and with plan first on, it MUST: the task runs as a pure planner whose only allowed tool is add_task. With self-verification on, every finished task queues a verification task — a fresh run that checks the work. Subtasks and verifications run before newer user tasks.

Everything is a file. Memories, logs, every LLM call, even the buttons (they set flag files). Open the agent_data/ folder in a text editor — you will see exactly what this dashboard shows.
