How this agent works

An AI agent is a loop around a language model. The model cannot do anything by itself — it can only write text. The loop (plain Python in agent.py, called the orchestrator) turns that text into actions:

  1. Build context — the three brain files, the tool list, all memories and the conversation so far are pasted into one big prompt.
  2. Ask the model — one ordinary HTTP request (see the LLM calls panel: nothing is hidden).
  3. The model picks a tool — its reply ends with a small JSON block like {"tool": "get_time", "args": {}}.
  4. Run the tool — the orchestrator executes that one function and appends the result to the conversation. Back to step 1.

The loop ends when the model calls the special tool finish — being done is just another tool call.

Tasks line up in a queue and run one at a time. The model can split big work into subtasks with its add_task tool — and with plan first on, it MUST: the task runs as a pure planner whose only allowed tool is add_task. With self-verification on, every finished task queues a verification task — a fresh run that checks the work. Subtasks and verifications run before newer user tasks.

Everything is a file. Memories, logs, every LLM call, even the buttons (they set flag files). Open the agent_data/ folder in a text editor — you will see exactly what this dashboard shows.

Things to try: turn on step-by-step mode and narrate each round · click LLM call #001 and find the brain files inside the request · edit KNOWLEDGE.md while a task runs · ask for an "angry" screen mood and watch the model recover from the tool error · give it a big multi-part task and watch it split off subtasks with add_task · turn on self-verification and watch a fresh run double-check the work · add a second model to .env (LLM_2_MODEL=…), pick it in the header and run the same task again — compare the two stories.

Why is some of it still English? The prompts, the tool descriptions, the tool results and everything the model writes are the conversation with the model — the dashboard shows them exactly as they are in the files. Only the dashboard's own words are translated (switch with EN | DE in the header).

Ein*e KI-Agent*in ist eine Schleife um ein Sprachmodell. Das Modell kann von sich aus nichts tun — es kann nur Text schreiben. Die Schleife (schlichtes Python in agent.py, der Orchestrator) macht aus diesem Text Handlungen:

  1. Kontext bauen — die drei Brain-Dateien, die Tool-Liste, alle Erinnerungen und die bisherige Unterhaltung werden zu einem großen Prompt zusammengeklebt.
  2. Modell fragen — ein ganz gewöhnlicher HTTP-Request (siehe das Panel LLM-Aufrufe: nichts ist versteckt).
  3. Das Modell wählt ein Tool — seine Antwort endet mit einem kleinen JSON-Block wie {"tool": "get_time", "args": {}}.
  4. Tool ausführen — der Orchestrator führt genau diese eine Funktion aus und hängt das Ergebnis an die Unterhaltung. Zurück zu Schritt 1.

Die Schleife endet, wenn das Modell das spezielle Tool finish aufruft — fertig zu sein ist einfach ein weiterer Tool-Aufruf.

Aufgaben stellen sich in eine Warteschlange und laufen nacheinander. Das Modell kann große Arbeit mit seinem Tool add_task in Teilaufgaben zerlegen — und mit Erst planen MUSS es das: Die Aufgabe läuft dann als reine*r Planer*in, deren*dessen einziges erlaubtes Tool add_task ist. Mit Selbstprüfung reiht jede abgeschlossene Aufgabe eine Prüfaufgabe ein — einen frischen Lauf, der die Arbeit kontrolliert. Teilaufgaben und Prüfungen laufen vor neueren Nutzer*innenaufgaben.

Alles ist eine Datei. Erinnerungen, Logs, jeder LLM-Aufruf, sogar die Knöpfe (sie setzen Flag-Dateien). Wer den Ordner agent_data/ in einem Texteditor öffnet, sieht genau das, was dieses Dashboard zeigt.

Zum Ausprobieren: den Schritt-für-Schritt-Modus einschalten und jede Runde kommentieren · LLM-Aufruf #001 öffnen und die Brain-Dateien in der Anfrage wiederfinden · KNOWLEDGE.md bearbeiten, während eine Aufgabe läuft · eine Screen-Stimmung „angry“ verlangen und zusehen, wie sich das Modell vom Tool-Fehler erholt · eine große mehrteilige Aufgabe stellen und beobachten, wie es Teilaufgaben mit add_task abspaltet · Selbstprüfung einschalten und einen frischen Lauf die Arbeit nachprüfen lassen · ein zweites Modell in .env eintragen (LLM_2_MODEL=…), es oben auswählen und dieselbe Aufgabe noch einmal laufen lassen — die beiden Geschichten vergleichen.

Warum bleibt manches Englisch? Die Prompts, die Tool-Beschreibungen, die Tool-Ergebnisse und alles, was das Modell selbst schreibt, sind die Unterhaltung mit dem Modell — das Dashboard zeigt sie genau so, wie sie in den Dateien stehen. Übersetzt sind nur die eigenen Worte des Dashboards (umschalten mit EN | DE im Kopf der Seite).
